# Coverage gate SA-review

Читать **после** группировки findings и **до** фиксации очереди. Не читать в начале прогона. Не показывать таблицу пользователю по умолчанию.

Не полный повторный анализ: не пересобирать карту, не перечитывать все артефакты, не искать дефекты «с нуля». Только проверить, что ни одна ветка ниже не была случайно пропущена.

Очередь нельзя зафиксировать, пока у каждой ветки нет ровно одного статуса.

Это не новый чек-лист и не замена матрицы в `applicability.md`.

## Ветки

Для каждой — `checked` / `not applicable` / `needs clarification`.

```text
UI / точки входа
platform differences
versions
API / contracts
data / models
events / analytics
admin
errors / edge cases
ecosystem / dependencies
development / testing tasks
```

Другие ветки матрицы (схема, решения, общие критерии качества) gate не заменяет.

## Статусы

| Статус | Когда |
| --- | --- |
| `checked` | Ветка была применимой или активирована связанной Jira, и evidence по ней реально смотрели |
| `not applicable` | Нет оснований, что ветка относится к изменению, **и** нет непроверенных связанных Jira, которые могли бы её включить |
| `needs clarification` | Неясно, применима ли ветка, или она выглядит применимой, но по сути не проверялась |

Ветка `needs clarification` должна попасть в очередь как вопрос. Нельзя оставить её только во внутреннем gate.

Нельзя ставить `not applicable` ради скорости или потому что ветка «не пригодилась» в уже собранных findings.

## Связанные Jira включают ветку

Связанные, дочерние и реализующие задачи сами по себе могут активировать ветку. Смотреть type, component, labels, summary, description.

Примеры сигналов: analytics / events / Snowplow; iOS / Android / Web; admin / Plaid Admin; Kafka / топик; коллекция / БД; development / testing.

Если такие задачи есть — нельзя объявлять ветку `not applicable`, пока их **содержание** не проверено (хотя бы summary и description в evidence summary). Существования ссылки недостаточно.

`platform differences`: отдельные задачи на iOS / Android / Web (или явное различие платформ в одной задаче) — нельзя закрыть `not applicable`, пока эти задачи не прочитаны. То же для `events / analytics` и `admin`.

Открыть пропущенную связанную задачу на этом шаге — точечно, по правилам `evidence-and-context.md`. Это не рестарт ядра.

## Если нашли пропуск

1. Опереться на уже собранные summary.
2. Если не хватает только непрочитанной связанной Jira или явно нужного объекта карты — открыть его, обновить summary, при необходимости дополнить очередь.
3. Не начинать ревью заново и не обходить все ссылки подряд.

## Запреты

- не выводить таблицу gate в пользовательский отзыв по умолчанию;
- не писать gate в tracked-файлы;
- не превращать непроверенную ветку в `not applicable`;
- не дублировать чек-лист.
