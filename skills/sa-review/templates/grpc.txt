Алгоритм работы *
Сценарий 1: Вызов из BFF
1. Инициация запроса
BFF отправляет запрос к сервису  на получение сущностей ( ).
2. Валидация запроса
Сервис проверяет корректность запроса:
Массив  ids[]  не должен быть пустым.
Все переданные  ids  должны соответствовать ожидаемому формату.
Параметр  platform  должен быть указан.
В случае ошибки валидации:
Возвращается ошибка ( errorCode ) с сообщением ( errorMessage ).
3. Поиск данных в кэше
Сервис проверяет наличие запрошенных  ids  в кэше.
Для каждого  id , отсутствующего в кэше:
Запрос сущности из БД:
Обращение к коллекции   для получения данных ( db.Entity.params[...] ).
4. Обработка результатов
В зависимости от количества элементов в массиве  ids :
Если 1 элемент: выполняется действие "что-то сделать".
Если 2 элемента: выполняется действие "что-то сделать другое".
Если 3 элемента: выполняется действие "что-то сделать совсем другое".
Опционально (если >3 элементов или массив пуст):
Очистка параметров сущности ( db.Entity.params[...] ) и запись одного параметра.
5. Возврат результата
Сервис возвращает BFF код  0 OK .
Сценарий 2: Вызов из AdminUI
1. Инициация запроса
AdminUI отправляет аналогичный запрос к сервису .
2. Валидация запроса
Проверка аналогична сценарию с BFF.
3. Выполнение алгоритма
Сервис выполняет "какой-то алгоритм" (детали не указаны).
4. Возврат результата
Сервис возвращает AdminUI код  0 OK .
