# Рабочая директория SA

Канон структуры для `sa-spec` и `sa-publish`. Не дублировать в каждом артефакте. Файл совпадает с `sa-spec/workspace.md`.

Путь:

```text
sa-work/<ISSUE-KEY>/
```

Создавать только реально необходимые директории и файлы.

## Дерево

```text
sa-work/
  <ISSUE-KEY>/
    context.md
    artifact-plan.md
    questions.md
    decisions.md
    publish-plan.md

    specs/
      feature.md

      http/
        *.md

      grpc/
        *.md

      kafka/
        *.md

      db/
        *.md

      ui/
        *.md

      algorithms/
        *.md

    review/
      self-check.md
      review.md
```

## Статусы локального артефакта

Человекочитаемые (писать в шапке файла и в `publish-plan.md`):

```text
Generated draft        — сгенерированный черновик, человек ещё не читал
Reviewed draft         — пользователь прочитал или поправил
Ready for review       — можно запускать sa-review
Approved               — утверждено после ревью
Published              — финализировано и опубликовано
```

Это статусы артефакта, не статусы Jira.

Старые подписи `Черновик`, `Проверено`, `Утверждено`, `Опубликовано` в уже лежащих папках считать так: Черновик → Generated draft, Утверждено → Approved, Опубликовано → Published. «Есть открытые вопросы» — не статус артефакта, а флаг в `questions.md`.

В шапке файла писать английский токен. В разговоре с пользователем можно русскую подпись из таблицы.

## `context.md`

Рабочий контекст, не спецификация. Не копировать огромные куски исходной документации.

```markdown
# <ISSUE-KEY>

## Цель

## Область изменений

## Затронутые компоненты

## Точки входа

## Контракты и версии

## Источники
- Jira:
- Confluence:
- Git:
- feature notes:

## Что явно не входит в изменение
```

Для каждой загруженной страницы Confluence фиксировать `pageId` и версию на момент загрузки (нужно `sa-publish` для проверки конфликтов).

## `artifact-plan.md`

После research и до генерации `specs/`. Пока плана нет — спецификации не писать.

В начале файла:

```markdown
# Artifact plan — <ISSUE-KEY>

План: ждёт подтверждения
Этап: planning
```

`План` — `ждёт подтверждения` или `подтверждён`. `Этап` — одно из: `research`, `planning`, `drafting`, `human-read`, `review`, `fix`, `approval`, `publish`. По этому полю видно, где остановились.

Блок на каждый артефакт:

```markdown
### GET /api/v1/example

Тип: HTTP
Операция: update
Файл: specs/http/get-example.md
Источник: Confluence pageId=...
Текущая версия: 17

Current state:
...

Изменения:
- update: алгоритм выбора
- add: вызов нового gRPC
- replace: описание fallback
- link: ссылка на новую gRPC-спецификацию

Основание:
- Jira CAT2-...
- D-004
- current state: ...

Затронутые компоненты:
- ...

Открытые вопросы:
- Q-003

Статус:
blocked

Готовность к генерации:
нет
```

Операция артефакта: `create`, `update`, `no-change`.

Типы фрагментов внутри документа: `add`, `replace`, `deprecate`, `link`, `no-change`. Смысл — [redline.md](../sa-spec/redline.md).

Статус блока: `blocked`, если есть нерешённый блокирующий `Q-NNN`; иначе `ready`. Утверждение из нерешённого блокирующего вопроса не генерировать.

Каждый change item ссылается на Jira requirement, источник, `D-NNN` или `Q-NNN`.

## `questions.md`

Все неразрешённые места. Нумерация `Q-001`, `Q-002`, … не переиспользовать номера.

```markdown
### Q-001 — Источник storeId

Статус: открыт
Тип: требует решения

Контекст:
...

Почему вопрос возник:
...

Варианты, найденные в источниках:
- header
- отдельное поле запроса

Решение:
—

Следующее действие:
—
```

Статусы вопроса:

```text
Открыт
Решён
Требует внешнего уточнения
Вынесен за рамки
Отложен
```

Типы (русские категории):

* **Блокирующий** — без решения нельзя корректно продолжить спецификацию.
* **Требует решения** — допустимо несколько вариантов.
* **Противоречие** — источники дают разные ответы.
* **Не найдено в источниках** — нужная информация отсутствует.
* **Можно оставить открытым** — не блокирует текущую поставку.

Дополнительно: `Ответственный:`, если статус «требует внешнего уточнения».

## `decisions.md`

После принятия решения переносить сюда, не оставлять только в списке вопросов.

```markdown
### D-004 — Источник storeId

Решение:
storeId передаётся в header ...

Причина:
...

Источник решения:
ответ пользователя, 2026-...

Затрагивает:
- GetLabels V3
- BFF
- feature.md
```

Нумерация `D-001` независима от `Q-*`. В записи вопроса после решения указать `Решение: D-004`.

Если решение должно жить в feature notes — предложить обновление этого файла, но не публиковать автоматически.

## Спецификации

В шапке каждого файла в `specs/`:

```markdown
---
задача: <ISSUE-KEY>
статус: Generated draft
тип: http
метод: GET
путь: /api/v3/example
описание: кратко зачем метод
swagger: url
аналоги: pageId=...
источник_confluence: pageId=... версия=17
---
```

Поля `метод` / `путь` / `описание` и заголовки секций (`## Алгоритм работы`, `## Запрос v1`) нужны `sa-publish`, чтобы залить данные в секции Confluence-шаблона, а не стереть его.

Каждый факт помечать одной категорией (в тексте или сноске, без выдуманной уверенности):

```text
подтверждено источником
следует однозначно из нескольких источников
решено пользователем
открытый вопрос
```

Не вставлять догадки как утверждения. Открытый вопрос — ссылка на `Q-NNN`, не молчаливый пробел.

## `publish-plan.md`

Главный вход для `sa-publish`. По одному блоку на файл.

Новая страница Confluence:

```markdown
### specs/http/get-labels-v3.md

Статус: Approved
Фаза: finalize

Назначение:
Confluence

Операция:
создать

Родительская страница:
pageId=...

Название:
GetLabels V3

Тип:
http
```

Существующая страница:

```markdown
### specs/http/get-example.md

Статус: Generated draft
Фаза: draft
Назначение: Confluence
Операция: обновить
pageId: 123456
Версия источника при загрузке: 17
Redline: yes
Human read: нет
SA review: нет
Approved: нет
Finalize: нет
Название: Get example

Draft publish выкладывает redline и не удаляет старый текст. Finalize — только при `Статус: Approved` и `Фаза: finalize`: зелёное становится обычным текстом, красное зачёркнутое удаляется, маркер черновика снимается.
```

Git:

```markdown
### specs/grpc/media.md

Статус: утверждено
Назначение: Git
Репозиторий: ...
Путь: docs/http/get-labels-v3.md
Операция: создать
```

После публикации `sa-publish` дописывает дату, URL/pageId/path, версию, commit.

## `review/`

- `self-check.md` — результат `sa-review` в режиме самопроверки по локальным артефактам.
- `review.md` — внешнее техническое ревью, если его просили отдельно.
