# SA — полный цикл

Одна команда. Три скилла по очереди. Правила не переписывать здесь — **читать и выполнять** соответствующий `SKILL.md`.

```text
sa-spec  →  sa-review (self-check)  →  утверждение  →  sa-publish
```

| Skill        | Ответственность                            |
| ------------ | ------------------------------------------ |
| `sa-spec`    | исследует, задаёт вопросы, пишет черновики |
| `sa-review`  | проверяет качество и полноту               |
| `sa-publish` | безопасно публикует утверждённое           |

Не публиковать и не утверждать молча. Стопы обязательны.

## Когда это, а когда отдельный скилл

| Фраза пользователя | Что запускать |
| --- | --- |
| полный цикл / весь пайплайн / от начала до публикации / сделай аналитику и опубликуй | этот скилл |
| собери аналитику / HTTP-спека / вопросы / разложи | только `sa-spec` |
| ревью / self-check / лид-ревью | только `sa-review` |
| опубликуй / выложи в Confluence | только `sa-publish` |

Если уже есть папка `sa-work/<ISSUE-KEY>/` — не начинать с нуля: определить, на каком шаге остановились, и продолжить.

## Файлы скиллов

Читать целиком в момент входа в шаг (не по памяти):

```text
~/.cursor/skills/sa-spec/SKILL.md
~/.cursor/skills/sa-review/SKILL.md
~/.cursor/skills/sa-publish/SKILL.md
```

Рабочая директория общая: `sa-work/<ISSUE-KEY>/` в workspace пользователя.

## Порядок

Копировать и отмечать:

```text
SA pipeline:
- [ ] Ключ задачи понятен
- [ ] Шаг 1: sa-spec (включая диалог по вопросам)
- [ ] Шаг 2: sa-review, режим самопроверка → review/self-check.md
- [ ] СТОП: показать итог, дождаться утверждения
- [ ] Шаг 3: sa-publish — только preview
- [ ] СТОП: дождаться что именно публиковать
- [ ] Apply по подтверждению
```

### Шаг 1 — `sa-spec`

Открыть `sa-spec/SKILL.md`. Режим по умолчанию для полного цикла: **полная аналитика**.

Дальше не идти, пока:

- блокирующие вопросы не решены или не вынесены за рамки / отложены пользователем;
- нет незафиксированных неизвестностей;
- написан `publish-plan.md`.

Если пользователь отвечает на вопросы — оставаться в `sa-spec` (обновить файлы), не перескакивать к публикации.

### Шаг 2 — `sa-review`

Открыть `sa-review/SKILL.md` и выполнить его с начала, включая вопрос про архитектурный анализ. Без явного ответа pipeline не продолжать. Режим: **самопроверка** по локальным артефактам.

`sa-spec` уже требует self-check перед готовностью. Если `review/self-check.md` свежий и после него спеки не менялись — не гонять второй раз, кратко сказать, что самопроверка уже есть.

Если self-check вернул новые неопределённости — назад в `sa-spec` (`questions.md`), не к публикации.

### СТОП — утверждение

Показать коротко:

- какие локальные файлы готовы;
- открытые неблокирующие вопросы;
- что уйдёт в Confluence / Git по плану.

Спросить явно, например:

```text
Самопроверка пройдена. Чтобы публиковать, нужно утверждение артефактов.

Утверждаю все готовые?
или: утверждаю только feature и HTTP
или: пока не публикуем
```

Без фразы вроде «утверждаю» / «можно публиковать» статус «Утверждено» не ставить и `sa-publish` на apply не вызывать.

Если пользователь сказал в исходной команде «и опубликуй», это **не** замена утверждения конкретных файлов. После self-check всё равно показать preview и спросить.

### Шаг 3 — `sa-publish`

Открыть `sa-publish/SKILL.md`.

1. Проставить «Утверждено» только тем файлам, которые пользователь утвердил.
2. Preview (CLI без `--apply`).
3. СТОП. Ждать «публикуй всё» / «только 1 и 3» / «Confluence да, Git нет».
4. Apply. Итоговый отчёт. `jira-write` — только отдельным «да».

## Ограничения

Нельзя:

- выполнять три скилла «в уме» без чтения их `SKILL.md`;
- публиковать в том же ходе, что написали черновик, без двух стопов;
- чинить замечания ревью правками «заодно» внутри publish;
- подменять `jira-write`.
