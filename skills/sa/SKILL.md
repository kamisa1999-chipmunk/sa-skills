# SA — полный цикл

Одна команда ведёт цепочку. Правила шагов не копировать: читать `SKILL.md` того скилла, в который входишь.

```text
sa-spec research
→ artifact-plan
→ подтверждение плана
→ generate / redline
→ человек читает
→ sa-review
→ правки
→ утверждение
→ sa-publish finalize
```

Старая схема «сразу self-check, потом публикация» не используется.

| Skill | Роль | Профиль |
| --- | --- | --- |
| `sa-spec` | research, план, черновики, правки findings | research / planning — high-reasoning; drafting — economical |
| `sa-review` | независимая проверка | independent-high-reasoning |
| `sa-publish` | draft или finalize уже подготовленного | economical |

Профили и запрет подменять модель: [../shared/model-routing.md](../shared/model-routing.md).

Файлы скиллов читать целиком в момент входа:

```text
~/.cursor/skills/sa-spec/SKILL.md
~/.cursor/skills/sa-review/SKILL.md
~/.cursor/skills/sa-publish/SKILL.md
```

Рабочая папка: `sa-work/<ISSUE-KEY>/`.

## Где остановились

Не начинать заново, если папка уже есть. Смотреть `artifact-plan.md` → `Этап`. Если поля нет:

| Что уже лежит | Этап |
| --- | --- |
| нет `context.md` | research |
| нет `artifact-plan.md` или план не подтверждён | planning, стоп |
| план подтверждён, нет `specs/` | drafting |
| спеки `Generated draft`, человек не подтвердил чтение | human-read, стоп |
| чтение есть, нет свежего `review/` | review |
| в review есть findings | fix, снова `sa-spec` |
| ревью чистое, нет `Approved` | approval, стоп |
| `Approved`, фаза не finalize | publish только после отдельного «finalize» |

Команды продолжения: «продолжи research», «покажи artifact plan», «план ок, генерируй», «прочитала, запускай review», «исправь findings», «перезапусти review», «finalize», «publish».

## Стопы

1. После плана — пока нет «план ок, генерируй» или заранее сказанного «генерируй без подтверждения плана для этой задачи».
2. После черновиков — список новых и изменённых страниц, неблокирующие вопросы, пути файлов. Review не запускать, пока нет «прочитала, запускай review». «Исправь сначала …» и «покажи изменения по …» остаются в `sa-spec`.
3. После чистого ревью — утверждение конкретных файлов. «Сделай аналитику и опубликуй» в исходной команде это подтверждение не заменяет.
4. Draft publish и finalize — разные подтверждения. Finalize не делать в том же шаге, что черновик.

## Review

Открыть `sa-review` и выполнить с начала, включая вопрос про архитектурный анализ. Без явного ответа дальше не идти.

Пакет только из артефактов: Story, requirements, specs, `artifact-plan.md`, `decisions.md`, evidence в `context.md`, чек-лист. Скрытые рассуждения writer в пакет не класть.

Запускать ревью отдельной сессией или агентом, если это возможно. Если нет — один раз написать, что ревью не полностью независимое, и критерии не смягчать.

Findings возвращать в `sa-spec`. Повторять ревью, пока результат не чистый. Внутри `sa-publish` findings не чинить.

## Publish

Открыть `sa-publish`.

- `Фаза: draft` — redline в Confluence, старый текст на месте, маркер черновика остаётся. Можно до ревью, если пользователь просит почитать в Confluence.
- `Фаза: finalize` — только после чтения, чистого ревью и явного «утверждаю» / «finalize». Статус файлов `Approved`.

Оба раза сначала preview, потом apply по явному «публикуй».
