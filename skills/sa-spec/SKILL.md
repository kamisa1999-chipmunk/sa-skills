# SA-spec

Research, план артефактов, затем черновики. Публикация — `sa-publish`. Проверка — отдельный `sa-review` после того, как человек прочитал черновик.

```text
research → artifact-plan → подтверждение плана → вопросы/решения
→ generate / redline → человек читает → (sa-review снаружи) → правки
```

Структура: [workspace.md](workspace.md). Источники: [sources.md](sources.md). Current state: [../shared/research-current-state.md](../shared/research-current-state.md). Redline: [redline.md](redline.md). Роли моделей: [../shared/model-routing.md](../shared/model-routing.md).

В ответе пользователю — русские названия. Токены не читать и не показывать.

Профили этого скилла: research и planning — high-reasoning; drafting — economical и только по утверждённому плану. Если модель внутри запуска не переключается — сказать это один раз и не делать вид, что переключилась. Drafting не меняет scope и не принимает новых решений.

## Принцип

Нет однозначного источника — не придумывать. Неопределённость → `questions.md` → решение пользователя → `decisions.md` → артефакты.

Нельзя генерировать утверждение из нерешённого блокирующего вопроса.

## Режимы

Определить режим до генерации. Генерации до плана нет ни в одном режиме, кроме явного «генерируй без подтверждения плана для этой задачи».

| Режим | Примеры | Где остановиться |
| --- | --- | --- |
| Полная аналитика | собери аналитику по CAT2-XXXX | план, затем черновики после подтверждения |
| Конкретная спецификация | сделай HTTP-спеку | план только по этому артефакту и связанным контрактам |
| Доработка | обнови спецификацию | current state и redline существующей страницы |
| Разложение | какие документы нужны | `artifact-plan.md`, без текста спек |
| Только вопросы | собери вопросы | research, `questions.md`, без спек |

## Порядок

Папка `sa-work/<ISSUE-KEY>/` уже есть — не начинать с нуля. Этап читать из `artifact-plan.md` (поле `Этап`) или по правилу в скилле `sa`.

```text
SA-spec:
- [ ] Режим и этап
- [ ] Research: sources.md + research-current-state.md
- [ ] context.md
- [ ] artifact-plan.md
- [ ] СТОП: summary плана, ждать подтверждения
- [ ] questions.md, диалог, decisions.md
- [ ] specs/ только по подтверждённому плану (redline.md)
- [ ] publish-plan.md со статусом Generated draft и Фаза: draft
```

Self-check из этого скилла не запускать. Ревью вызывает оркестратор `sa` после фразы вроде «прочитала, запускай review».

## Research

Обязательный current state — когда меняются поведение, API, gRPC, контракты, хранение, интеграции, клиенты, алгоритмы выбора / fallback / priority, admin-flow. Список проверок и правило `Cannot verify` — в `research-current-state.md`.

Классы рисков оттуда учесть при плане и тексте. Пайплайн `sa-review` сюда не копировать.

## План

После исследования записать `artifact-plan.md` (форма в workspace). Показать коротко:

- что создать;
- что обновить;
- что не менять;
- какие решения уже есть;
- какие вопросы блокируют генерацию.

Дальше не идти, пока пользователь не скажет «план ок, генерируй» или заранее «генерируй без подтверждения плана для этой задачи». Для простой задачи само продолжение только если это явно разрешено в команде.

Во время генерации всплыл новый блокер: остановить этот артефакт, добавить `Q-NNN`, обновить план, решение не выдумывать.

## Вопросы

Как раньше: полный список, без дублей, блокирующие сверху. Четыре и больше — сначала заголовки, потом по одному.

Статусы вопроса: Открыт, Решён, Требует внешнего уточнения, Вынесен за рамки, Отложен.

После ответа: `questions.md`, `decisions.md`, связанные пункты плана и уже написанные черновики. В вопросе указать `Решение: D-004`.

## Генерация

Только пункты плана со статусом `ready`. Шаблон типа — живая страница или снимок, см. sources.md. Для нового типа — 1–3 аналога как образец структуры, не как источник требований.

Существующая страница — только redline из `redline.md`. Новая — шаблон и маркер `Generated draft / Сгенерированный черновик`.

Не описывать внутренности чужого компонента на его странице. Один алгоритм не копировать в несколько документов: ссылка на каноническую спеку.

Каждый факт: подтверждено источником, следует однозначно, решено пользователем (`D-NNN`) или открытый вопрос (`Q-NNN`).

Статус новых и изменённых файлов: `Generated draft`. В `publish-plan.md` фаза `draft`.

## Правки после ревью

Findings чинит этот скилл, не `sa-publish`: правка draft/redline, при необходимости снова чтение человеком. Критерии ревью не пересматривать «потому что writer уже объяснил».

## Ограничения

Нельзя:

- писать спеки до `artifact-plan.md`;
- публиковать в Confluence, Git или Jira;
- молча удалять или переписывать существующий абзац;
- принимать продуктовое или архитектурное решение без evidence;
- читать все репозитории без подтверждённой зависимости;
- ставить `Approved` или `Published`;
- запускать `sa-review` вместо отдельного этапа.
