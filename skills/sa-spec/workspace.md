# Рабочая директория SA

Канон структуры для `sa-spec` и `sa-publish`. Не дублировать в каждом артефакте.

Путь:

```text
sa-work/<ISSUE-KEY>/
```

Создавать только реально необходимые директории и файлы.

## Дерево

```text
sa-work/
  <ISSUE-KEY>/
    context.md
    questions.md
    decisions.md
    publish-plan.md

    specs/
      feature.md

      http/
        *.md

      grpc/
        *.md

      kafka/
        *.md

      db/
        *.md

      ui/
        *.md

      algorithms/
        *.md

    review/
      self-check.md
      review.md
```

## Статусы локального артефакта

Человекочитаемые (писать в шапке файла и в `publish-plan.md`):

```text
Черновик
Есть открытые вопросы
Готово к ревью
Проверено
Утверждено
Опубликовано
```

Машинные значения при необходимости — отдельным полем `status_id` в `publish-plan.md`, не вместо русского статуса.

## `context.md`

Рабочий контекст, не спецификация. Не копировать огромные куски исходной документации.

```markdown
# <ISSUE-KEY>

## Цель

## Область изменений

## Затронутые компоненты

## Точки входа

## Контракты и версии

## Источники
- Jira:
- Confluence:
- Git:
- feature notes:

## Что явно не входит в изменение
```

Для каждой загруженной страницы Confluence фиксировать `pageId` и версию на момент загрузки (нужно `sa-publish` для проверки конфликтов).

## `questions.md`

Все неразрешённые места. Нумерация `Q-001`, `Q-002`, … не переиспользовать номера.

```markdown
### Q-001 — Источник storeId

Статус: открыт
Тип: требует решения

Контекст:
...

Почему вопрос возник:
...

Варианты, найденные в источниках:
- header
- отдельное поле запроса

Решение:
—

Следующее действие:
—
```

Статусы вопроса:

```text
Открыт
Решён
Требует внешнего уточнения
Вынесен за рамки
Отложен
```

Типы (русские категории):

* **Блокирующий** — без решения нельзя корректно продолжить спецификацию.
* **Требует решения** — допустимо несколько вариантов.
* **Противоречие** — источники дают разные ответы.
* **Не найдено в источниках** — нужная информация отсутствует.
* **Можно оставить открытым** — не блокирует текущую поставку.

Дополнительно: `Ответственный:`, если статус «требует внешнего уточнения».

## `decisions.md`

После принятия решения переносить сюда, не оставлять только в списке вопросов.

```markdown
### D-004 — Источник storeId

Решение:
storeId передаётся в header ...

Причина:
...

Источник решения:
ответ пользователя, 2026-...

Затрагивает:
- GetLabels V3
- BFF
- feature.md
```

Нумерация `D-001` независима от `Q-*`. В записи вопроса после решения указать `Решение: D-004`.

Если решение должно жить в feature notes — предложить обновление этого файла, но не публиковать автоматически.

## Спецификации

В шапке каждого файла в `specs/`:

```markdown
---
задача: <ISSUE-KEY>
статус: Черновик
тип: http
метод: GET
путь: /api/v3/example
описание: кратко зачем метод
swagger: url
аналоги: pageId=...
источник_confluence: pageId=... версия=17
---
```

Поля `метод` / `путь` / `описание` и заголовки секций (`## Алгоритм работы`, `## Запрос v1`) нужны `sa-publish`, чтобы залить данные в секции Confluence-шаблона, а не стереть его.

Каждый факт помечать одной категорией (в тексте или сноске, без выдуманной уверенности):

```text
подтверждено источником
следует однозначно из нескольких источников
решено пользователем
открытый вопрос
```

Не вставлять догадки как утверждения. Открытый вопрос — ссылка на `Q-NNN`, не молчаливый пробел.

## `publish-plan.md`

Главный вход для `sa-publish`. По одному блоку на файл.

Новая страница Confluence:

```markdown
### specs/http/get-labels-v3.md

Статус: утверждено

Назначение:
Confluence

Операция:
создать

Родительская страница:
pageId=...

Название:
GetLabels V3

Тип:
http
```

Существующая страница:

```markdown
### specs/db/product-label-store.md

Статус: утверждено
Назначение: Confluence
Операция: обновить
pageId: 123456
Версия источника при загрузке: 17
Название: ProductLabel_{storeId}
```

Git:

```markdown
### specs/grpc/media.md

Статус: утверждено
Назначение: Git
Репозиторий: ...
Путь: docs/http/get-labels-v3.md
Операция: создать
```

После публикации `sa-publish` дописывает дату, URL/pageId/path, версию, commit.

## `review/`

- `self-check.md` — результат `sa-review` в режиме самопроверки по локальным артефактам.
- `review.md` — внешнее техническое ревью, если его просили отдельно.
