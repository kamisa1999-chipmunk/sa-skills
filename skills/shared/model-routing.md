# Model routing

Политика ролей. Конкретные имена моделей здесь не задаются.

Профили:

| Профиль | Этап |
| --- | --- |
| `research` | current state, затронутые компоненты, producer → contract → consumer, код, зависимости, неизвестности |
| `planning` | `artifact-plan.md`, create / update / no-change, типы правок, блокирующие решения |
| `drafting` | шаблон, текст, redline, ссылки, согласованность с `decisions.md` |
| `review` | независимый `sa-review` |
| `publish` | применение уже утверждённого redline, снятие разметки, `publish-plan.md`, публикация |

Рекомендуемая сила профиля:

- `research`, `planning` — high-reasoning;
- `drafting`, `publish` — economical, только после зафиксированного решения;
- `review` — independent-high-reasoning, отдельная сессия или агент, если runtime это умеет.

Соответствие профиля конкретной модели задаётся в настройках оркестрации, не в тексте скилла.

Если runtime не умеет сменить модель внутри одного запуска:

- граница этапа всё равно явная, этап можно запустить отдельным вызовом;
- не писать, что модель переключилась;
- пайплайн из-за этого не останавливать.

## Кто что не делает

Drafting не меняет scope и не принимает новые продуктовые или архитектурные решения. Новая неопределённость на drafting: остановить этот артефакт, завести `Q-NNN`, вернуть в planning / research.

Publish не принимает содержательных решений и не чинит findings.

Review не получает скрытые рассуждения writer, незафиксированные предположения и внутренний контекст, которого нет в артефактах. Пакет на ревью: Story, requirements, specs, `artifact-plan.md`, `decisions.md`, evidence current state, чек-лист.

Если review идёт в той же сессии и изоляция невозможна — во внутреннем состоянии пометить, что ревью не полностью независимое. Критерии ревью из-за этого не смягчать.

High-reasoning не тратить на механические шаги, когда решение уже записано. Качество research и review экономией токенов не снижать.
